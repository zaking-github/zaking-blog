# Tailwind CSS 是什么

Tailwind CSS 是一种 **Utility-First** 的 CSS 框架。它不强调先写一套组件样式，再在页面里复用，而是通过大量语义明确的工具类，直接组合出最终界面。

例如下面这段代码：

```tsx
export function Hero() {
  return (
    <section className="mx-auto max-w-4xl px-6 py-16 text-center">
      <h1 className="text-4xl font-bold tracking-tight text-zinc-900">
        Build faster with Tailwind CSS
      </h1>
      <p className="mt-4 text-base leading-7 text-zinc-600">
        使用原子类快速构建现代化界面，而不是反复编写样式文件。
      </p>
    </section>
  )
}
```

相比传统写法，Tailwind 的核心优势主要有 3 个：

1. **开发速度快**：大部分样式可以直接在模板中完成。
2. **命名成本低**：不需要为每个区块单独设计 class 名。
3. **一致性更强**：颜色、间距、圆角、字体等设计值更容易统一。

## 为什么很多项目选择 Tailwind CSS

传统 CSS 在项目变大后，常见问题包括：

- 样式命名越来越困难
- 无用样式不断累积
- 组件之间容易相互影响
- 响应式和状态样式维护成本高

Tailwind 的做法是把这些问题拆解成稳定的小单位。例如：

- `p-4` 表示内边距
- `text-lg` 表示字号
- `rounded-xl` 表示圆角
- `bg-blue-600` 表示背景色

你不再频繁切换 HTML 和 CSS 文件，而是在组件附近完成绝大多数样式表达。

## 如何安装 Tailwind CSS

如果你使用的是 Next.js、Vite、React 或 Vue 项目，通常都可以直接集成 Tailwind。以现代前端项目为例，安装思路一般分为两步：

1. 安装 Tailwind CSS
2. 在全局样式入口中引入 Tailwind

在 Tailwind CSS v4 中，配置方式相比过去更简单，很多场景下只需要在 CSS 文件中引入：

```css
@import "tailwindcss";
```

如果你的项目已经完成了 Tailwind 集成，那么接下来最重要的不是安装命令，而是理解它的写法规则。

## 核心语法：从常用工具类开始

Tailwind 的类名通常都很直观，可以大致按以下几类理解。

### 1. 布局类

```html
<div class="container mx-auto flex items-center justify-between"></div>
```

- `container`：容器宽度
- `mx-auto`：水平居中
- `flex`：启用 Flex 布局
- `items-center`：交叉轴居中
- `justify-between`：主轴两端对齐

### 2. 间距类

```html
<div class="p-6 mt-8 gap-4"></div>
```

- `p-6`：内边距
- `mt-8`：上外边距
- `gap-4`：子元素间距

Tailwind 的间距体系非常适合统一设计规范，避免页面里充满随意的 `13px`、`22px`。

### 3. 字体与文本类

```html
<h2 class="text-2xl font-semibold tracking-tight text-zinc-900"></h2>
```

- `text-2xl`：文字大小
- `font-semibold`：字重
- `tracking-tight`：字间距
- `text-zinc-900`：文字颜色

### 4. 背景、边框与阴影

```html
<div class="rounded-2xl border border-zinc-200 bg-white shadow-sm"></div>
```

- `rounded-2xl`：圆角
- `border`：边框
- `bg-white`：背景色
- `shadow-sm`：阴影

## 响应式设计怎么写

Tailwind 的响应式写法非常直接，通过断点前缀来控制不同屏幕下的样式：

```html
<div class="grid grid-cols-1 gap-6 md:grid-cols-2 xl:grid-cols-4"></div>
```

这段代码的意思是：

- 默认情况下 1 列
- `md` 屏幕及以上显示 2 列
- `xl` 屏幕及以上显示 4 列

常见思路是先写移动端默认样式，再逐步向大屏增强，这就是典型的 **Mobile First**。

再看一个按钮区布局：

```html
<div class="flex flex-col gap-3 sm:flex-row">
  <button class="rounded-lg bg-black px-4 py-2 text-white">开始使用</button>
  <button class="rounded-lg border px-4 py-2">查看文档</button>
</div>
```

这里的含义是：

- 小屏幕下按钮纵向排列
- 到 `sm` 及以上改成横向排列

## 状态样式与交互写法

Tailwind 另一个非常高频的能力是状态前缀。常见的包括：

- `hover:` 鼠标悬停
- `focus:` 获取焦点
- `active:` 按下状态
- `disabled:` 禁用状态
- `dark:` 暗黑模式

例如：

```html
<button
  class="rounded-lg bg-blue-600 px-4 py-2 text-white transition hover:bg-blue-700 focus:outline-none focus:ring-2 focus:ring-blue-400 disabled:cursor-not-allowed disabled:opacity-50"
>
  提交
</button>
```

这类写法的好处是状态逻辑和组件结构放在一起，不需要再额外跳到 CSS 文件里查找对应选择器。

## 实战示例：做一个卡片组件

下面通过一个实际例子把常见类串起来：

```tsx
type ArticleCardProps = {
  title: string
  description: string
  tag: string
}

export function ArticleCard({ title, description, tag }: ArticleCardProps) {
  return (
    <article className="group rounded-2xl border border-zinc-200 bg-white p-6 shadow-sm transition hover:-translate-y-1 hover:shadow-md">
      <span className="inline-flex rounded-full bg-zinc-100 px-3 py-1 text-xs font-medium text-zinc-600">
        {tag}
      </span>

      <h3 className="mt-4 text-xl font-semibold text-zinc-900 group-hover:text-blue-600">
        {title}
      </h3>

      <p className="mt-3 text-sm leading-6 text-zinc-600">
        {description}
      </p>

      <a
        href="#"
        className="mt-6 inline-flex text-sm font-medium text-blue-600 hover:text-blue-700"
      >
        阅读全文
      </a>
    </article>
  )
}
```

这个例子覆盖了几类典型能力：

- 卡片容器：圆角、边框、阴影、过渡
- 分组联动：`group` 和 `group-hover:`
- 内容排版：标题、描述、标签
- 交互反馈：悬停上移和颜色变化

在博客、后台、官网、控制台这类页面里，这种写法非常常见。

## Tailwind 的常见实践建议

Tailwind 虽然很好用，但如果不控制使用方式，代码也可能变得冗长。下面是几个比较实用的建议。

### 1. 优先写清晰的结构，再优化类名长度

不要一开始就急着抽象。先把页面做出来，再判断哪些部分值得封装成组件。

### 2. 重复三次以上再考虑抽组件

如果一个按钮、卡片、表单块在多个地方重复出现，就应该把它抽成 React 或 Vue 组件，而不是只复制一串 class。

### 3. 设计值尽量保持统一

比如间距统一用一套节奏：

- 小间距用 `2`、`3`、`4`
- 模块间距用 `6`、`8`
- 大区块间距用 `12`、`16`

统一节奏比“每个地方都差不多但不完全一样”更重要。

### 4. 不要把所有逻辑都塞进一个 `className`

当类名特别长时，可以考虑：

- 拆组件
- 条件类名组合
- 抽出变体函数

例如在 React 里常见这样的写法：

```tsx
import { cn } from "@/lib/utils"

type ButtonProps = {
  primary?: boolean
}

export function Button({ primary = false }: ButtonProps) {
  return (
    <button
      className={cn(
        "rounded-lg px-4 py-2 text-sm font-medium transition",
        primary
          ? "bg-blue-600 text-white hover:bg-blue-700"
          : "border border-zinc-300 bg-white text-zinc-900 hover:bg-zinc-50"
      )}
    >
      Click me
    </button>
  )
}
```

这样比手写大量字符串拼接更清晰。

## Tailwind CSS 适合什么项目

Tailwind 非常适合下面这类场景：

- 中后台系统
- 内容型网站和博客
- SaaS 官网
- 组件化前端项目
- 需要快速验证设计的产品原型

如果你的团队希望：

- 保持一致的设计语言
- 提高页面开发效率
- 降低样式维护成本

那么 Tailwind 往往是一个非常现实的选择。

## 总结

Tailwind CSS 的本质，不是“少写 CSS”，而是用一套稳定、可组合、可约束的方式来管理界面样式。

你可以把它理解为一种新的样式组织方法：

- 用工具类表达视觉结果
- 用组件承载复用逻辑
- 用统一设计值保证整体一致性

如果你刚开始学习 Tailwind，建议先掌握这 4 个部分：

1. 间距、颜色、字体、边框这些基础工具类
2. 响应式断点写法
3. `hover:`、`focus:`、`dark:` 这类状态前缀
4. 在 React 或 Next.js 组件中组织 `className` 的方式

掌握这些之后，你已经可以独立完成大部分中小型页面的样式开发了。
